# 0008. Career outreach and interview prep (Rationale)

## Context

Job applicants face steep challenges after tailoring their resume for an applicant tracking system. Cold outreach on platforms like LinkedIn and direct email drastically improves interview conversion rates, but crafting customized pitches that connect specific candidate projects to employer requirements is time consuming and difficult to sustain across dozens of applications. Furthermore, LinkedIn enforces a strict 300 character limit on connection notes, causing unoptimized invitations to truncate awkwardly or lose key impact.

Once an application advances, candidates must prepare for behavioral and technical interviews. Standard interview cheat sheets generated by generic AI tools suffer from two dangerous failure modes: hallucinating fabricated metrics that embarrass candidates when grilled by interviewers, and offering generic textbook advice detached from the candidate's authentic history. A candidate who claims a 40 percent database latency reduction without having built the underlying query optimization will fail technical vetting.

CareerCraft AI operates on a Bring Your Own Key (BYOK) architecture with complete data privacy, bilingual English and Arabic support, and strict applicant tracking system compliance. The application already models candidate profiles, work experiences, projects, and target job postings, storing tailored resumes with unused JSON columns for outreach and interview prep. The challenge is designing an architecture that decouples outreach copy generation from interview cheat sheet generation while keeping them integrated into a seamless candidate studio.

## Options considered

### Option 1: Decoupled umbrella specification with dedicated child specs and modular Server Actions

In this approach, career outreach and interview prep are treated as two distinct sub domains under a single umbrella specification. Cold outreach is defined in `0008-career-outreach.md` and interview prep is defined in `0008-interview-prep.md`. Both rely on dedicated Server Actions using Vercel AI SDK generateObject with typed Zod schemas, persisting structured payloads into existing JSON columns on TailoredResume. Studio navigation integrates both as distinct tabs alongside the Resume Editor and ATS Workbench.

**Pros**:

- Decouples messaging rules and character constraints from interview STAR framing and anti hallucination logic.
- Allows independent implementation, testing, and evolution of each capability without bloated single spec files.
- Maintains a clean shared contract for database columns, authentication, encryption, and studio sub navigation.
- Bounded question counts (exactly 3 questions + 3 interviewer questions) prevent server action timeouts and limit BYOK token costs.

**Cons**:

- Requires maintaining three spec files (umbrella index, outreach child, and interview prep child) instead of one monolithic document.

### Option 2: Monolithic single specification combining outreach and interview prep

In this approach, all outreach message generation and interview cheat sheet requirements are combined into a single continuous specification file without child specs.

**Pros**:

- Single file to read and reference during initial build.

**Cons**:

- Bloats the specification document with two materially different user jobs and API surfaces.
- Increases cognitive load when reviewing or implementing either feature in isolation.

### Option 3: Separate top level specifications splitting the project scope into Slice 4a and Slice 4b

In this approach, career outreach becomes spec `0008-career-outreach` and interview prep becomes spec `0009-interview-prep`, requiring a split of scope row 9 into two separate scope features.

**Pros**:

- Totally independent scope milestones in `docs/scope/scope.md`.

**Cons**:

- Fractures the cohesive Slice 4 delivery thread established in the project roadmap and PRD.
- Adds scope management overhead for two capabilities that naturally deploy together inside the Tailor Studio.

## Rationale

We chose Option 1 because an umbrella specification provides the best architectural structure for complex multi faceted features.

Decoupling into two dedicated child specifications (`0008-career-outreach.md` and `0008-interview-prep.md`) isolates the specific rules of each domain: LinkedIn character counters, recipient targeting, and cold email subjects in the outreach spec, versus bounded STAR categories, anti hallucination bracketed placeholders, and print stylesheets in the interview prep spec.

At the same time, the umbrella `index.md` anchors the shared architectural contract: unified `TailoredResume` JSON persistence, zero database migrations, shared BYOK key decryption, synchronized studio tab navigation, and concurrency guards. This mirrors the project's existing high quality architecture.
