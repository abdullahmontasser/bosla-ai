## Summary

This change implements the design system and bilingual user interface foundation for CareerCraft AI (spec 0003), introducing Tailwind CSS v4 semantic tokens, accessible Radix UI primitives, next-themes dark mode, and Next.js App Router subpath localization (`/[lang]`) for Arabic and English. While typography integration, token definitions, and Server/Client Component boundaries are solidly structured, changes are requested due to unresolved Major issues from the prior review: an overbroad regex in middleware that hijacks valid two-letter application routes (such as `/cv` or `/me`) causing false 404 errors, and completely missing test coverage for middleware routing and interactive foundation components (`LanguageSwitcher`, `Dialog`, `DropdownMenu`).

## Major

### 🟠 Overbroad regex in middleware hijacks valid 2-letter application routes, `src/middleware.ts:37`

**Problem**: The middleware checks `if (/^[a-zA-Z]{2}(-[a-zA-Z0-9]+)?$/.test(firstSegment))` to pass unsupported language codes through to the localized layout where `notFound()` is invoked. Because this regex matches any two-letter string, any unlocalized top-level application route beginning with a two-letter slug (such as `/cv`, `/me`, `/ai`, `/pr`, `/qa`, or `/hr`) is mistakenly treated as an unsupported locale instead of being redirected to `/${defaultLocale}/<path>`.
**Why it matters**: In CareerCraft AI, navigating directly to `/cv` or `/me` bypasses the locale redirect logic and triggers a 404 `notFound()`, breaking top-level routing conventions and preventing users from accessing core application endpoints directly.
**Suggested fix**: Avoid treating arbitrary 2-letter path segments as locale codes. Instead, maintain an explicit set or ISO lookup table of known language codes to pass through, or let unlocalized paths always redirect to `/${targetLocale}${pathname}` so standard application routes resolve properly within `/[lang]`.

### 🟠 Untested middleware routing logic and interactive foundation components, `src/middleware.ts:1` & `src/components/ui/components.test.tsx:1`

**Problem**: There is no test suite for `src/middleware.ts`, leaving its cookie resolution (`NEXT_LOCALE`), `Accept-Language` header parsing, 307 redirect URL generation, search query parameter retention, and matcher exclusion rules completely unverified. Furthermore, `src/components/ui/components.test.tsx` only tests `Button`, `Input`, `Textarea`, `Badge`, `Card`, and `RtlIcon`; it omits tests for `LanguageSwitcher` (which is explicitly mandated by AC-10 in spec 0003), `ThemeSwitcher`, `Dialog`, and `DropdownMenu`.
**Why it matters**: Routing middleware is a critical gatekeeper for internationalization and application delivery. Without automated test coverage in a configured test environment, routing regressions, infinite redirect loops, or broken locale detection will escape into production undetected.
**Suggested fix**: Create `src/middleware.test.ts` using Vitest to test root redirects, cookie precedence, Accept-Language parsing, and search parameter preservation. Expand `src/components/ui/components.test.tsx` to verify `LanguageSwitcher` (cookie setting and route navigation), `ThemeSwitcher`, and accessible dialog opening/closing behavior.

## Minor

### 🟡 Accept-Language parser ignores RFC 9110 quality weights and matches invalid language tags, `src/middleware.ts:17`

**Problem**: The parser splits the `Accept-Language` header by comma, strips parameters, and iterates sequentially without parsing or sorting by the quality factor (`q=...`). Furthermore, it matches locales using `lang.startsWith('ar')` and `lang.startsWith('en')`.
**Why it matters**: A browser header sending `en;q=0.3, ar;q=0.9` will be assigned English because `en` appears first in the string, disregarding the user's explicit preference for Arabic. Additionally, `lang.startsWith('ar')` erroneously matches unrelated 3-letter ISO language tags like `arn` (Mapudungun) or `arp` (Arapaho) as Arabic.
**Suggested fix**: Parse `q` quality weights to sort candidate languages in descending preference order, respect `q=0` as rejected, and enforce exact language tag boundaries (`lang === 'ar' || lang.startsWith('ar-')` and `lang === 'en' || lang.startsWith('en-')`).

### 🟡 Root path (`/`) redirect includes trailing slash causing secondary redirect, `src/middleware.ts:43`

**Problem**: When a user accesses `/`, `redirectUrl` evaluates to `/${targetLocale}/` (e.g., `/en/`). Because Next.js defaults to `trailingSlash: false`, Next.js immediately responds with an HTTP 308 permanent redirect from `/en/` to `/en`.
**Why it matters**: Every first-time visitor hitting the root URL undergoes two consecutive HTTP redirects (307 temporary redirect followed by 308 permanent redirect), adding unnecessary network roundtrips and degrading initial page load latency.
**Suggested fix**: Normalize the path when constructing the redirect URL: if `pathname === '/'`, redirect directly to `/${targetLocale}` without a trailing slash.

### 🟡 LanguageSwitcher drops query parameters and URL hash fragments, `src/components/ui/language-switcher.tsx:49`

**Problem**: `LanguageSwitcher` derives its target path solely from `usePathname()` via `segments.join('/')`, ignoring query parameters and URL hashes.
**Why it matters**: Switching languages on pages with search queries, pagination, or filter flags (e.g. `?search=engineer&page=2`) discards all parameters, resetting the user's current view and filtering context.
**Suggested fix**: Read `useSearchParams()` (or `window.location.search`) and append the existing query string to `newPath` before calling `router.push()`.

### 🟡 Prettier code formatting check fails across 6 repository files, `src/app/[lang]/design-system/page.tsx:1`

**Problem**: `npm run format:check` reports code style violations in 6 files, including `design.md`, `src/app/[lang]/design-system/page.tsx`, `src/components/ui/badge.tsx`, `src/components/ui/button.tsx`, and `src/components/ui/card.tsx`.
**Why it matters**: Unformatted files violate the project's explicit formatting conventions defined in `AGENTS.md` and will block pre-commit checks (`lint-staged`) or fail CI build pipelines.
**Suggested fix**: Run `npm run format` (`prettier --write .`) to align all modified files with repository formatting rules.
